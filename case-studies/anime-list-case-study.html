Case Study — Content Catalog

Anime List

A media catalog built around fast, intuitive browsing — giving anime fans a clean space to discover, filter, and track titles without friction.

JavaScript Responsive UI API Integration Catalog Layout
Back to Projects View Live Source Code

What was the brief?

The goal was to build a media catalog where users could browse anime titles quickly, see key information at a glance, and enjoy the experience across any screen size.

The challenge was balancing information density with visual breathing room — a catalog that shows enough to make decisions without overwhelming the viewer. I also wanted the data to feel live, not static, which pushed me toward API integration.

What decisions did I make and why?

  • Card-first layout: Each anime gets a consistent card with cover art, title, genre tags, and a rating — keeping scanning fast and predictable.
  • API-driven data: Pulling real anime metadata from an external source keeps the catalog fresh and shows I can work with live data, not just hardcoded content.
  • Filter and search logic: JavaScript-driven filtering lets users narrow results by genre or search by title without a page reload — keeping the experience snappy.
  • Responsive grid: The card grid reflows from 4 columns on desktop to a single column on mobile, so the catalog is equally usable on a phone.
  • Hover interactions: Subtle scale and overlay effects on card hover add depth without slowing the browsing experience.

Tools, technologies, and what I learned

Stack used

  • Vanilla JavaScript (ES6+)
  • CSS Grid and Flexbox
  • Fetch API for data
  • Responsive design patterns
  • Vercel for deployment

Key learnings

  • How to structure a real-time filter without a framework — pure DOM manipulation at scale.
  • The importance of skeleton loading states when API data takes time to arrive.
  • How to balance content density in a catalog so the grid never feels cluttered or too sparse.
  • Working with external API pagination and mapping the response into a consistent UI structure.

What would I do differently? What am I proud of?

Given more time I would add user-side lists — favourites, watchlist, completed — backed by localStorage or a lightweight backend. Personalisation turns a catalog into a tool.

I'd also improve the search with fuzzy matching so minor spelling differences still return relevant results.

What I'm proud of is the filtering speed and the clean visual rhythm of the cards. The grid feels considered, not just thrown together, and the API integration works reliably even on slow connections.

Design thinking

The catalog deliberately keeps navigation minimal — the grid is the interface. Color accents are reserved for genre tags and ratings so they pop without competing with the cover art.
